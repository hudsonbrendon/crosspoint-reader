# File Browser Sorting — Design

**Status:** Approved (design phase)
**Date:** 2026-06-08
**Author:** Hudson Brendon (with Claude)

## Goal

Let the user sort the file browser by **Name**, **Date modified**, or **File size**, instead of only natural alphabetical order. Works on both X3 and X4 (filesystem-only data, no hardware dependency, no EPUB metadata parsing).

## Motivation

Today `FileBrowserActivity` always sorts entries by `FsHelpers::sortFileList` (natural alphabetical, directories first). There is no way to surface a just-copied book or browse by size. The three chosen criteria are all cheap to obtain from the filesystem, so they add real value without RAM pressure or per-folder parsing.

## Decisions (locked during brainstorming)

- **Criteria offered:** Name (natural, default), Date modified (newest first), File size (largest first).
- **Direction:** Fixed per criterion (no asc/desc toggle). Three modes total.
- **Persistence:** Global, stored in `InkPointSettings` (one mode for the whole browser, survives reboot).
- **Control surface:** A `SettingInfo::Enum` entry in Settings → Display. No in-browser control this iteration.
- **Directories:** Always listed first and always name-sorted (natural), regardless of mode. The sort mode applies to files only.
- **Excluded:** Title/Author (metadata) sorting; web file-transfer listing; `BmpViewerActivity` sibling-image ordering (stays name-sorted).

## Architecture

The change is deliberately contained. Only `FileBrowserActivity::loadFiles()` changes behaviourally; a small reusable comparator is factored out of `FsHelpers`, a small accessor is added to the HAL, and the setting/enum/i18n are wired through the existing settings system.

### 1. Setting

`src/InkPointSettings.h`:
```cpp
enum FILE_SORT_MODE : uint8_t {
  SORT_NAME = 0,           // natural alphabetical (default, current behaviour)
  SORT_DATE_MODIFIED = 1,  // newest first
  SORT_SIZE = 2,           // largest first
  FILE_SORT_MODE_COUNT
};
...
// File browser sort mode (filesystem-only; works on X3 and X4)
uint8_t fileSortMode = SORT_NAME;
```

`src/SettingsList.h` (Display category, near the other browser/display settings):
```cpp
SettingInfo::Enum(StrId::STR_FILE_SORT, &InkPointSettings::fileSortMode,
                  {StrId::STR_SORT_NAME, StrId::STR_SORT_DATE, StrId::STR_SORT_SIZE},
                  "fileSortMode", StrId::STR_CAT_DISPLAY),
```
- JSON key `"fileSortMode"` matches the field name → automatic persistence via `JsonSettingsIO` and automatic web-UI exposure.
- Device settings UI and web settings page are both generated by the existing `SettingInfo::Enum` machinery — no new activity.

### 3. Data collection and sorting (`FileBrowserActivity::loadFiles()`)

The current loop opens each `HalFile`, reads its name, filters by extension/mode, and `emplace_back`s the name string into `std::vector<std::string> files`. `files` is then consumed in ~24 places (`files[selectorIndex]`, `getFileName(files[index])`, `findEntry`, rendering callbacks). **That type and all consumers stay unchanged.**

New approach inside `loadFiles()` only:

1. Collect into a temporary local vector of a small struct (file-local, anonymous namespace):
   ```cpp
   struct BrowserEntry {
     std::string name;  // includes trailing '/' for directories
     uint32_t date;     // FAT modify key; 0 if unavailable
     uint32_t size;     // bytes; 0 for directories
   };
   ```
   For each kept entry, while its `HalFile` is still open, capture:
   - `name` (existing `getName` path),
   - `size = file.isDirectory() ? 0 : file.fileSize()` (existing accessor),
   - `date = file.modifiedKey()` (new HAL accessor, see §4).
   Use `entries.reserve()` is not possible (count unknown up front) — acceptable; this is a transient vector, and the project rule about `reserve()` is best-effort when the size is unknown.

2. Sort `entries` with a comparator that:
   - puts directories before files (`isDir` from trailing `/`),
   - sorts **directories** among themselves by `FsHelpers::naturalLess(name, name)` always,
   - sorts **files** among themselves by the active `SETTINGS.fileSortMode`:
     - `SORT_NAME` → `naturalLess(a.name, b.name)`,
     - `SORT_DATE_MODIFIED` → `a.date > b.date` (newest first), tie-break `naturalLess`,
     - `SORT_SIZE` → `a.size > b.size` (largest first), tie-break `naturalLess`.

3. Write names back:
   ```cpp
   files.clear();
   files.reserve(entries.size());
   for (auto& e : entries) files.push_back(std::move(e.name));
   ```

No change to `FileBrowserActivity.h`. No change to rendering/selection/open logic.

### 4. HAL addition

`HalFile` currently exposes `getName`, `size`, `fileSize`, `seek`, `position` — but no modification time. Add a single accessor wrapping SdFat's `FsFile::getModifyDateTime(uint16_t* pdate, uint16_t* ptime)`:

```cpp
// In HalFile: returns a monotonically-orderable FAT modify key, (date << 16) | time.
// Returns 0 if the timestamp is unavailable. Takes the storage mutex like other HalFile methods.
uint32_t modifiedKey();
```

Implementation reads the underlying `FsFile` modify date/time through the existing `Impl` and combines them: `(uint32_t(pdate) << 16) | ptime`. FAT date/time fields are already ordered (year>month>day, hour>min>sec packed), so the combined key sorts chronologically. On failure (`getModifyDateTime` returns false), return `0`.

> The exact SdFat method name/signature must be confirmed against the vendored SdFat in the implementation step; `getModifyDateTime` is the documented API. If unavailable, fall back to `0` for all files (date sort degrades to tie-break-by-name) and flag it.

### 5. Reusable natural comparator

Extract the existing natural-sort lambda body from `FsHelpers::sortFileList` into a named function:
```cpp
// FsHelpers.h
bool naturalLess(const std::string& a, const std::string& b);  // case/number-aware, no dir-first logic
```
`sortFileList` is rewritten to call `naturalLess` (behaviour identical). `FileBrowserActivity` uses `naturalLess` for name mode, directory ordering, and tie-breaking. `BmpViewerActivity` keeps calling `sortFileList` unchanged.

> Note: the current `sortFileList` lambda also encodes "directories first" (trailing `/`). `naturalLess` is the pure name comparator WITHOUT the dir-first rule; the dir-first rule moves into the callers (`sortFileList` keeps it; `FileBrowserActivity`'s comparator applies it explicitly). This keeps `naturalLess` single-purpose and reusable.

## Data Flow

```
loadFiles()
  └─ for each dir entry (HalFile open):
        capture name + size(fileSize) + date(modifiedKey)  → BrowserEntry
  └─ std::sort(entries, comparator(SETTINGS.fileSortMode))   // dirs first; dirs by name; files by mode
  └─ files = [e.name for e in entries]                       // back to vector<string>
render() / selection / open  ── unchanged (operate on files) ──
```

## Edge Cases

- **No valid timestamp:** `modifiedKey()` returns `0`; entry sorts to the bottom in date mode. Predictable, never crashes.
- **Ties** (same date or same size): broken by `naturalLess` for a stable, deterministic order.
- **Directories in date/size mode:** ignored by the file comparator; dirs always name-sorted and first.
- **Empty folder / load failure:** existing early-returns preserved; `files` stays empty.
- **PickFirmware mode:** same sorting applies to the filtered `.bin` list (harmless; firmware files sort by the chosen mode like any file).
- **Mode change while browsing:** the setting is read in `loadFiles()`; the new order takes effect next time the folder is loaded (on browser entry / navigation / refresh). No live re-sort of the current view is required this iteration.

## Out of Scope

- Title/Author (EPUB metadata) sorting — costly parsing, and the list shows filenames not titles.
- Per-folder sort memory.
- Ascending/descending toggle.
- In-browser quick-cycle control.
- Web file-transfer listing order.
- `BmpViewerActivity` sibling ordering.

## Testing

- **Build:** `pio run` is the compile gate. NOTE: the local PlatformIO build is currently broken by a pre-existing environment issue (`ModuleNotFoundError: No module named 'littlefs'` — Homebrew Python 3.14 / pyexpat ABI on macOS 26). The authoritative gate is CI (`ci.yml`, which installs PlatformIO via `uv pip install --system` on Linux).
- **Static analysis:** `pio check` on changed files.
- **Format:** clang-format.
- **Manual (human, both X3 and X4 — feature is hardware-agnostic):**
  - Settings → Display shows "File Sorting" with Name / Date Modified / File Size.
  - Name: directories first, natural alphabetical (unchanged from today).
  - Date Modified: a freshly-copied file appears at the top.
  - File Size: largest file first; directories still grouped first by name.
  - Setting persists across reboot.
  - Folder with files lacking timestamps does not crash and orders predictably.
- No cache format version bump (no `book.bin`/`section.bin` structure change).
